# v2 optimisation log

This document records **what was wrong** and **what was changed** during the
v2 cleanup, so future readers (and reviewers) do not have to re-derive it from
the diff. Numbers refer to the state of `main` at commit `c1a4e2e`
(2025-11-12).

---

## 1. Repository hygiene (the biggest problem)

| Symptom | Measurement | Fix |
|---|---|---|
| A virtual environment was committed | `.venv/` → **34,120 files, ~900 MB**, 97 % of the repo | removed from tracking, added to `.gitignore`, documented purge recipe |
| Vector store committed | `storage/chroma_db` → `chroma.sqlite3` **48 MB** + HNSW binaries | untracked; regenerated by `python -m src.ingest` |
| Byte-code committed | `src/**/__pycache__/*.pyc` | untracked |
| Secrets committed | `.env` with a live LangSmith key (`lsv2_pt_…`) and a Qwen API key (`sk-…`) in a **public** repo | untracked, `.gitignore` hardened, `.env.example` added, rotation steps in `docs/SECURITY.md` |

Effect: `git clone` goes from ~300 MB to a few MB, and no credentials leak.

> Removing the files from the tip does **not** remove them from history. Run
> `scripts/purge-history.sh` (git-filter-repo) and **rotate the keys**.

## 2. Duplicated code (one implementation, four copies)

`retrieve_context` + `answer_question` existed in:

* `src/eval/eval_ragas.py`
* `src/eval/eval_newv.py` (a re-formatted copy of the file above — 95 % identical)
* `src/eval/ask_one.py`
* `serve_api.py` (via `from src.eval.eval_ragas import …`)

Fixes:

* new `src/rag/` package — `embedding.py`, `store.py`, `retriever.py`,
  `answering.py`, plus the dependency-free `ranking.py`;
* `eval_newv.py` is now a 30-line alias that flips `--loop` on;
* `serve_api.py` and `ask_one.py` import only `src.rag` — starting the API no
  longer imports `ragas`, `datasets` or `pandas`;
* the two eval scripts now share `src/eval/common.py` (score normalisation,
  cache keys, evidence heuristics).

## 3. Correctness bugs

| Bug | Consequence | Fix |
|---|---|---|
| `generate()` used `state["messages"][-1].content` as the context | after a rewrite the "context" was the rewritten *question*, so the model answered with no evidence | documents are stored explicitly in the state and rendered with source + page |
| `rewrite → agent` had no counter | a model that keeps emitting tool calls loops forever | `steps` in the state + `MAX_AGENT_STEPS` + `recursion_limit` |
| `evaluate_documents()` branched on `len(content) > 50` | an empty answer or a short clause flipped the branch unpredictably | routing depends on whether documents were retrieved |
| `Chroma` + embeddings built at import time | `import src.app_graph` downloaded models and crashed without an index | lazy singletons, side-effect-free imports |
| `data/eval/testset.csv`, `experiments/*.csv` were relative to the CWD | scripts only worked from the repo root (`loop_run.py` had to `cd` there) | paths resolved against `REPO_ROOT` in `src/config.py` |
| re-ingest appended duplicate chunks; `--reset` did not exist | growing, duplicated index | deterministic chunk ids + `--reset` |
| `allow_origins=["*"]` **and** `allow_credentials=True` in CORS | invalid combination, silently rejected by browsers | origins from `CORS_ORIGINS`, credentials disabled |
| `@app.on_event("startup")` | deprecated and removed in modern FastAPI | `lifespan` handler |

## 4. Performance

| Change | Why |
|---|---|
| `CrossEncoder` cached per model | it was instantiated **inside** `retrieve_context`, i.e. reloaded for every question |
| embeddings + vector store are process-wide singletons | the 90 MB embedding model was loaded 6× per run |
| chains cached per `(prompt, llm)` | the LCEL chain was rebuilt on every call |
| batch ingest with `flush=True` progress | no more silent stalls |
| text-only imports | `import src.eval.ask_one` went from "loads ragas + pandas" to a few hundred ms |

`--rerank` note: the committed `.venv` did **not** contain `sentence-transformers`,
so `CE_AVAILABLE` was `False` and every historical "rerank=True" run silently
fell back to plain similarity ordering. `requirements.txt` now pins
`sentence-transformers` explicitly, and the pipeline logs/behaves deterministically
when it is missing.

## 5. Engineering scaffolding

* `pyproject.toml` (metadata, hatchling build, `[project.scripts]`, ruff,
  pytest, mypy, coverage);
* `requirements.txt` pinned to the versions recovered from the committed `.venv`
  (langchain 0.3.27, langgraph 0.6.7, chromadb 1.0.20, ragas 0.3.4, …) — the old
  file had **no version at all** and was missing `fastapi`,
  `sentence-transformers` and `uvicorn`, so a fresh install could not serve or
  re-rank;
* `tests/` — 68 tests, all runnable without model downloads (pure ranking rules,
  score normalisation, config parsing);
* GitHub Actions CI: ruff + pytest on Python 3.10/3.11/3.12;
* `Makefile`, `Dockerfile`, `docker-compose.yml` (app + Ollama);
* `LICENSE` (MIT), `.env.example`, rewritten `README.md`,
  `docs/SECURITY.md`, `scripts/purge-history.sh`.

## 6. Deliberately *not* changed

* the prompt templates — changing them would invalidate the answer cache and
  make the historical `experiments/*.csv` numbers incomparable;
* the RAGAS schema / CSV columns — same reason;
* the qwen2.5 defaults and Ollama-only stack — no cloud dependency was added.
